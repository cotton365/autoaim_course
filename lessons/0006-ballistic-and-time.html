Lesson 0006 · 时间/开火层

时间与开火：命中时刻不是开火时刻

0005 把状态推到 t_hit；但子弹要飞，云台要转。命中点和开火角之间隔着一条弹道，开火时刻和命中时刻之间隔着一段飞行时间。

预计 30 分钟先修：0002、0005对应代码：trajectory.cpp / ballistic_trajectory.hpp / Planner.cpp

本节结束时你能 推导真空弹道的二次方程，说出高/低弧怎么选；写出阻力弹道的 A,B,C；解释 T_fly 不动点为什么收敛；估算“只算一次”会差多少；说清云台到位和开火窗口的关系。

1. 两个时刻：t_hit 与 t_fire

自瞄的最终目标是“在 t_hit 让弹丸和装甲板相遇”。但弹丸不是瞬间到达的：

t_hit = t_now + t_latency + T_fly
t_fire = t_hit - T_fly

预测层给的是 p_target(t_hit)；控制层要在 t_fire 把云台指到“从这个角度打出去，能在 t_hit 命中”的角度。两者之间是弹道逆解：

p_hit = p_target(t_hit)
(yaw_fire, pitch_fire) = BallisticInverse(p_hit, v0, g, drag)

把时间轴拆开：

sp:     frame t_k → track(t_k) → t_now → +delay → t_fire → +T_fly(iterate) → t_hit
wuhan:  frame t_k → track → buffer → 1kHz predict(t_now) → +T_fly(iterate)+delay → t_hit
SHtech: frame t_k → track → t_now → +(now-t_k)+latency+T_fly(one shot) → t_hit

2. 弹道：从发射角到命中点

先看真空。目标在水平距离 d、高差 h，初速 v0，重力 g。设发射角 θ，飞行时间：

T = d / (v0 cosθ)

h = v0 sinθ · T - ½ g T²
  = d tanθ - ½ g d² (1+tan²θ) / v0²

令 u=tanθ，整理成二次方程：

(g d² / 2v0²) u² - d u + (g d² / 2v0² + h) = 0

a = g d² / (2v0²)
b = -d
c = a + h
u = (-b ± √(b² - 4ac)) / (2a)

两个解：+√ 是高弧，-√ 是低弧。低弧飞行时间短、弹道平，通常更适合自瞄；高弧在近距离会把弹道抬得很高，容易碰云台/超出俯仰，远距离又飞得久。sp 在 trajectory.cpp:29 比较 t1/t2 取短时间（低弧）；SHtech 用重力补偿近似低弧；wuhan 先取高弧、无效再低弧。

高弧陷阱 高弧解在数学上只要判别式 ≥0 就存在，但飞行时间可能是低弧的 20 倍。wuhan 的 solve_pitch() 先返回 p1（高弧）；在 RM 常见距离，p1 经常超过 60° 被上层丢弃，只有在远距离/高初速/高阻力时才会真正选中。读代码时不要只看“返回了 p1”，要看调用方有没有角度/时间过滤。

wuhan 的阻力模型只把阻力加在水平方向，竖直方向仍只受重力：

x(t) = ln(1 + k v0 cosθ · t) / k
z(t) = v0 sinθ · t - ½ g t²

T = (e^{kd} - 1) / (k v0 cosθ)

A = (e^{kd} - 1)/k
C = A/v0
B = ½ g C²
B u² - A u + (B + h) = 0

这是一个工程近似；k 通常很小，远距离才明显。它的好处是仍有闭式解，坏处是低估了竖直方向的阻力。

3. T_fly 是不动点

命中时刻依赖飞行时间，飞行时间又依赖命中点：

t_hit = t_now + t_latency + T_fly
T_fly = range( p_target(t_hit) ) / (v0 cosθ)

所以 T_fly 是不动点。迭代：

T_0 = range(t_now + latency) / v0
for k = 0..N:
    p_k = p_target(t_now + latency + T_k)
    T_{k+1} = range(p_k) / (v0 cosθ_k)

收敛速度取决于目标径向速度与弹速之比。弹速 23 m/s、目标 4 m/s，比值约 0.17，迭代 2–3 次就够；sp/wuhan 用 10 次是留余量。

4. “只算一次”会差多少

SHtech 的装甲板模型：

T = cal_fly_time(p_now)
aim = p_now + v · (latency + T)

它假设“飞行时间内目标匀速”，但没有把 aim 的新位置再代回去更新 T。误差量级：

ΔT ≈ (v_target · T) / v0
Δaim ≈ v_target · ΔT

目标 4 m/s、T=0.15 s、v0=23：ΔT≈0.026 s，Δaim≈10 cm。对 13.5 cm 的装甲板，这已经是一个不可忽略的偏差。所以“一次性”是用精度换计算量，不是等价替换。

5. 云台到位与开火窗口

预测层给出 t_hit 的命中点，控制层要回答两个问题：

  • 云台能不能在 t_fire 之前转到 yaw_fire, pitch_fire？
  • 转到之后，角度误差是否小到可以开火？

装甲板在图像里的角尺寸约 α ≈ w/d。如果云台角误差大于 α/2，子弹就可能擦边。工程上不直接算“命中概率”，而是用“角度误差 + 角速度 + 稳定时间”做开火门控：

error = angle(current_gimbal, aim_angle)
if error < α/2 and |ω_gimbal| < threshold and stable_time > t_settle:
    fire()

三套代码的分工：

项目时间/弹道开火门控
spaimer.cpp:32 延迟 + 飞行时间不动点；trajectory.cpp 弹道Shooter 的稳定/角度门控
wuhanvery_aimer.cpp:224 命中点迭代；ballistic_trajectory.hpp:43 阻力弹道fire_advice + MPC 轨迹误差
SHtechPlanner.cpp:536 重力补偿；:568 参考轨迹轨迹跟踪误差 + 策略层开火条件

“云台从当前角转到目标角”的时间没有塞进 t_hit，而是通过“参考轨迹 + 跟踪误差 + 开火门控”保证开枪时已经到位。这是预测层和控制层的分工：预测层给“命中点”，控制层判断“现在能不能打”。

6. MPC 参考轨迹为什么是“每个时刻的命中角”

wuhan/SHtech 都会采样一条参考轨迹：

for t in [-H/2·dt, ..., +H/2·dt]:
    p_t = target.predict(t)
    cp(t) = gimbal_angle_to_hit(p_t)   # 若在 t 时刻开火，云台该指哪

这条轨迹的横轴是“开火时刻”，纵轴是“对应的云台角”。MPC 跟踪它，等价于“让云台提前走到未来某个开火时刻所需的角”，从而在连续射击时保持超前。中心时刻取 now 还是 t_hit，取决于实现。

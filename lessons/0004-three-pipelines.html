Lesson 0004 · 机械/观测层

从四角到车状态：PnP 能给什么，不能给什么

自瞄的第一件事，是把一帧图像里的四个角点，变成“车在哪、朝哪、转多快”。这一节只做这一层：几何、PnP、可观测性、关联；滤波留到下一节。

预计 30 分钟先修：0002对应代码：target.cpp / armor_target.cpp / Tracker.cpp

本节结束时你能 说出单板 PnP 的 6DoF 和整车状态的差别；解释为什么单帧的车心/半径不可靠；画出 detector → PnP → 关联 → 滤波 的链；说出三套代码各自把什么当观测。

1. 先看一帧：四个角点能告诉我们什么

相机看到一块装甲板的四个角。角点的像素坐标是 detector 给的；装甲板的宽高是已知的（大板/小板）。把这两样东西交给 PnP，解出的是这块板在相机系里的 6DoF 位姿：

T_i = [ R_i, p_i ]        # 板中心 p_i，板姿态 R_i
P_ij = T_i · P̄_j          # 四个角 P̄_j 投到相机系

但自瞄要的是整辆车。车心和板心的关系是刚体几何：

p_i = c + R(θ) · u_i
u_i = ( -r_i cosφ_i, -r_i sinφ_i, Δz_i )
φ_i = i · 2π/N            # N=4 普通车，N=3 前哨站

把一帧里的角色分清楚：

层输入输出它不知道什么
detector图像四个角点的像素、板别深度、姿态、车心
PnP四角 + 板尺寸单板 6DoF：p_i, R_i车心、半径、速度、角速度
tracker多帧单板位姿车状态 c, v, θ, ω, r, h目标下一步怎么机动

detector、PnP、tracker 是三件事。把 PnP 的输出直接叫“车的位置”，后面的滤波和选板都会跟着错。

2. 单帧 PnP 的 6DoF 不是车状态

PnP 给的是板心 p_i 和板法向。由几何式反推车心：

c = p_i - R(θ) · u_i

看起来只差一个减法，但 θ、r_i、Δz_i 并不都是已知的：

  • 板法向能给出 θ + φ_i，但 PnP 的法向有双解、有噪声；
  • r_i 随车型变化，前后板与左右板还不一定相同；
  • Δz_i 也不一定为 0，前哨站尤其如此。

如果半径已知、板别已知、法向可信，单板确实能反推一个 c；但实际条件下，这个 c 的误差会被半径误差和法向误差放大。更稳的做法是把 r_i 也放进状态，用多帧运动约束去估：

x = [ c, v, θ, ω, r1, r2, h ]

这就是“单帧 PnP”与“整车状态”的差别：PnP 是观测，状态是滤波器要估的东西。

数值后验 0.5 px 角点噪声、6 m 距离：PnP 深度平均绝对误差约 4.1%（约 247 mm）；yaw 标准差约 1.45°。忽略装甲板 15° 俯仰时，解出的 yaw 偏 −3.7°、深度偏 +3.5%。这些误差直接进滤波器，所以 R 不能拍脑袋。

还有一个容易被忽略的点：平面 PnP 天然有两个解。两个解都能把四个角重投影得很好，但姿态可能差很多。工程上要用“正面朝相机”、装甲板 15° 俯仰先验、时间连续性来选：

200 次 0.5px 噪声：IPPE 全部给出双解，且两解都“正面”
裸 solvePnP 选错镜像支：80/200，旋转误差 23.39°
加 15° pitch 先验后：旋转误差 6.63°

这不是 PnP 实现错了，而是平面目标的几何多解。先验和时序一致性是观测层的一部分。

3. 三套代码怎么把观测变成状态

三套代码的差别，首先在“拿什么当观测”。它们都没有直接把“车心”送进滤波器，而是各自选了一种测量：

项目观测 z状态为什么这样选
spPnP 后转球坐标：[yaw, pitch, distance, armor_yaw]11D：[x,vx,y,vy,z,vz,θ,ω,r,l,h]yaw/pitch/d 和云台角直接对应，H 可解析；代价是 PnP 深度噪声直接进 R
wuhan灯条端点的图像投影：每条灯条 4 维 [angle, cx, cy, len]13D：[c, v, R(3), ω, log r1, log r2, h]绕开 PnP 的深度/姿态误差，单灯条也能用；代价是投影非线性强，H 要数值求
SHtechPnP 后转直角坐标：[y_a, x_a, z_a, θ_a]11D：[y,vy,x,vx,z,vz,θ,ω,r,l,h]H 简单，R 的各向异性好构造；代价是同样吃 PnP 噪声

注意 SHtech 的状态顺序是 y 在前，不是 x 在前。它的 H 列顺序、R 的 XY 块都跟着这个顺序走；读代码时先对齐顺序，再看公式。

把三套代码的观测链摊开：

sp:      corners → solvePnP → [yaw,pitch,d,armor_yaw] → EKF
wuhan:   corners → 灯条端点 → 投影残差 → ESKF（批量、迭代 5 次）
SHtech:  corners → solvePnP → [y_a,x_a,z_a,θ_a] → IESEKF

它们的状态维数不同，但都在做同一件事：用“当前状态下的板应该在哪”去解释“传感器看到的板在哪”。

4. 关联：四块板怎么对应到同一辆车

一帧里可能看到 0 块、1 块、2 块、4 块板。看到多块时，要先回答“这块板属于哪辆车、是几号板”，否则滤波器会把两块板的位置混在一起。

  • sp：按装甲板 ID/类型和跟踪器里的目标匹配，选最近的板；tracker.cpp 里维护目标列表。
  • wuhan：armor_target.cpp:508 用四边形的形状/位置代价做匹配，再决定这一帧哪些灯条属于同一辆车。
  • SHtech：predict_closest_armor() 用预测位置找最近板；它的几何展开和 h() 在同一个 ID 上差 180°（p_i = h_{i+2}），但四块板的集合相同，Hausdorff 只有 0.62 mm；实际瞄准按“最近板”选点不受影响，受影响的是 armor_index/开火 ID 的一致性。

关联错了，后面的滤波会“看起来很正常地”跟错板。工程上通常加三道保险：

1. 门控：新观测和预测位置差太远 → 丢掉
2. 代价：形状、ID、朝向、时间连续性一起打分
3. 滞回：锁定一块板后，不因为一帧抖动就换板

5. 这一层留给下一层什么

观测层的输出不是“一个点”，而是一组带不确定度的状态和关联结果：

给滤波器的：
  z, R                  # 这一帧测到了什么，有多准
  association           # 这块板属于哪辆车、几号板
  x0, P0                # 初始化：第一帧/第一组多板
  quality               # 遮挡、双解、距离、板别是否可信

下一节才回答：有了这些观测，怎么把状态推到 t_hit，以及为什么需要 EKF/ESKF/IEKF 这些不同的线性化。

常见误区 “PnP 解出了板中心，所以车心就是板中心减半径。”只有在半径、板别、法向都可信时才成立。单帧 PnP 的深度误差、平面双解、半径未知，任何一个都会让这个减法偏几十厘米。
